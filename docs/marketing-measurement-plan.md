# マーケティング計測・運用メモ

## 目的

広告費をかけずに、山本マイカーセンターのサイト改善を数字で判断できる状態にする。

見るべき数字はPVだけではなく、問い合わせに近い行動を中心にする。

## 集客を二つの経路で見る

同じ28日間で前期比較し、ローカルWeb検索とAI回答からの発見を分けて判断する。どちらも最終的には中古車の条件相談、電話発信などの実際の相談につながったかを確認する。業者からの仕入れ・整備相談も成果として扱う。

### ローカルWeb検索

- Search Console: `used-cars/`、`new-cars/`、`bankin-toso/`、`insurance-repair/`、`shaken/`、`business/` の表示・クリック・CTRを見る。地域名を含む検索語は別表で確認するが、地域名を省く近隣ユーザーもいるため、これだけをローカル流入の総数と呼ばない。
- Googleビジネスプロフィール: 管理画面で検索表示、電話、経路、サイトクリックを月ごとに記録する。住所、営業時間、サービス、写真の内容とサイトの記載が一致しているか確認する。実際の作業写真・お客様の自然な口コミを優先し、架空の事例や数字を足さない。
- GA4: 上記ページの閲覧だけでなく、`phone_dial`、`phone_prompt_open`、`goo_net_click` を確認する。在庫閲覧と条件からの仕入れ相談は別の意図として読む。
- 変更判断: 表示はあるがクリックされないページはタイトル・説明文を一度に一要素だけ見直し、少なくとも次の28日間を観察する。順位や需要の変動があるため、厳密なA/Bテストとは呼ばない。

### AI回答からの発見

- GA4: レポートの `Identifiable AI referrals` でChatGPT、Perplexity、Claude、Gemini、Copilot等の識別できる参照元を確認する。AI回答を読んだだけの人や、参照元の付かない訪問は含まれない。既存の `llm_referral_visit` イベントも補助指標にする。
- Google Search Consoleの生成AIパフォーマンスはAI Overviews / AI Modeでのリンク表示回数、Bing Webmaster ToolsのAI Performanceは対応サービスでの引用・参照ページ・グラウンディングクエリーの集計を管理画面で月次確認する。Googleのこのレポートには現時点でクリック・CTR・検索語の内訳はない。Bingも全引用の完全なログではない。通常のWeb検索指標と合算しない。
- 質問に短く直接答える本文、実際の対応範囲、会社情報、関連する既存記事へのリンクを保つ。`robots.txt` で検索クローラーを妨げず、構造化データは画面にある事実と一致させる。AI向けの特別なファイルや定型文を順位改善策として扱わない。
- 引用や参照元が少数の間は増減を成果と断定しない。問い合わせ時に「どこで知ったか」を聞けた場合は、個人情報を載せずに月次で集計する。

### 引用・訪問・相談を分ける（2026-10-04）

- ChatGPTの検索リンクには `utm_source=chatgpt.com` が付くと公式案内がある。既存の `analytics-head.js` はこのUTMと既知のAIドメインの参照元を検出する。本番ホスト限定・計測除外を維持し、閲覧やテストを人の訪問として追加送信しない。
- 回答に引用されても誰もリンクを押さなければ、GA4/Clarityでは分からない。参照元の欠落、Cookie削除、別端末、計測ブロックによる欠測もある。サイト側のJavaScriptだけで全AIサービスの引用回数を取得できるとは説明しない。
- Google/BingのAI管理画面のデータは現在の接続済みレポートに自動取得していない。未取得をゼロと扱わない。管理権限と表示対象の有無を確認し、利用できればCSV等の公式エクスポートを別の証拠として保存する。
- 仕入れ相談の案内を見た `used_car_consultation_view` と、フロー・電話案内への `used_car_consultation_click` を追加する。前者は対象セクションごとに1ページ読み込み1回、後者はクリックごとの意向で、成立した相談件数ではない。GA4セッション参照元を合わせてAI流入後の行動も確認できる。
- 定期レポートで `goo_net_click` と上記のイベントを `newVsReturning`、セッション参照元、ページ、イベント数・ユーザー数・セッション数に分ける。新規・再訪はGA4で観測できた訪問の区分で、個人・業者の判別や同一人物の証明ではない。行ごとのユーザー数を足し合わせない。
- 新イベントの計測開始は今回の本番反映以降。過去の閲覧から相談意向を遡って推定しない。納期が理由で相談しなかったかは計測だけでは分からず、電話時に聞けた内容を補助にする。
- 公式資料: [OpenAIのパブリッシャーFAQ](https://help.openai.com/en/articles/12627856)、[Googleの生成AIパフォーマンス](https://support.google.com/webmasters/answer/16984139?hl=en)、[BingのAI Performance](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c)。確認日: 2026-10-04。

## 入れるツール

- Google Search Console: 検索キーワード、表示回数、クリック、掲載順位、インデックス状況を見る。
- Google Analytics 4: ページ閲覧、電話クリック、Goo-net遷移、採用フォーム送信開始/成功、CTAクリック、スクロール到達率を見る。
- Microsoft Clarity: ヒートマップと録画で、どこを読まれているか、どこで迷っているかを見る。採用ページも対象とし、応募フォームと送信結果は明示的にマスクする。

## サイト側の設定

`analytics-head.js` の設定オブジェクトにIDを入れる。このファイルは本番ドメインでのみGA4とClarityを起動し、AI回答からの流入イベントも画面初期化とは独立して送る。`analytics.js` はクリック等の独自イベントを担当する。

### 人のアクセスとAIによる取得を混同しない（2026-09-28）

- GA4のセッションはブラウザーで計測できた訪問。人の実人数を保証する数字ではない。AI参照元のセッションはその内数で、足し合わせない。
- `llm_referral_visit` は既知のAI参照元・UTMが確認できたページ読み込み。GA4のセッション帰属とは定義が違うため、同数を期待しない。日付とランディングページをレポートで確認する。
- `observe-crawlers` は既知のUser-Agent（ChatGPT-User、OAI-SearchBot、GPTBot、Claude-User、Claude-SearchBot、ClaudeBot、Perplexity-User、PerplexityBot、Googlebot、bingbot）のリクエストにだけ実行する。成功した公開HTMLの「日本時間の日付・宣言されたエージェント・用途・ページ」をBlobsに保存。通常ブラウザーにはこの処理を実行しない。未登録・ブラウザー偽装のエージェントは計測範囲外。GA4やClarityへクローラーイベントは送らない。
- 保存単位は1日・エージェント・ページごとの取得有無。同じ日の繰り返し取得を訪問件数として数えない。IP、User-Agent全文、クエリー、参照元、Cookieは保存しない。90日で削除する。
- エージェントは自己申告情報で、IPによる本人確認はしていない。取得は引用・掲載・学習への採用の証拠ではない。GooglebotやBingbotは検索クローラーとして区別し、AI専用アクセスとは呼ばない。
- 計測開始前は「不明」。取得エラーもゼロ件と扱わない。診断用リクエストは `X-MCC-Crawler-Test: 1` で別領域に保存し、通常レポートから除く。
- 読み出しは `crawler-report` にBearer認証を要求。256ビットのランダム秘密値はローカルの `~/Codex/.codex-secrets/crawler-report.json` に保存し、コードにはSHA-256の照合用ハッシュのみを置く。ハッシュそのものでは認証できない。秘密値はリポジトリ、公開ディレクトリ、レポート本文へ保存しない。Netlifyの `MCC_CRAWLER_REPORT_TOKEN` が有効な場合はそちらを優先するが、環境変数の反映に依存せず認証できる。キー交換時は手元の秘密値と照合用ハッシュを両方更新し、環境変数を使用している場合はそちらも更新する。
- 既存Netlify環境のEdge Functions／Blobsを使用する。契約変更は行わず、実行回数・ストレージ利用はNetlifyの使用量として増えるため定期的に確認する。

```js
window.MCC_ANALYTICS = {
  ga4Id: 'G-XXXXXXXXXX',
  clarityId: 'xxxxxxxxxx',
  enableScrollDepth: true,
  enableCtaTracking: true,
  enableVisibilityTracking: true
};
```

採用フォームと送信結果には `data-clarity-mask="true"` を付け、録画へ入力値を送信しない。

## GA4で見るイベント

- `phone_prompt_open`: PCで電話番号の案内を開いた。電話相談への意向として扱う。
- `phone_dial`: スマホ等の電話リンク、またはPCの番号案内内の発信リンクが押された。接続・通話の成立までは確認できない。
- `phone_click`: 共有の計測対象外で追加された電話リンク用の予備イベント。日常の判断には使わない。
- `goo_net_click`: Goo-netへ遷移した
- `used_car_consultation_view`: 仕入れ相談の案内セクションが表示された
- `used_car_consultation_click`: 仕入れ相談の流れ・電話案内へ進むリンクが押された。`consultation_action` は `flow` / `phone`。パラメーターをGA4画面の独立した軸で見るにはカスタムディメンション登録が別途必要だが、イベント名・ページ・参照元・新規再訪は既存のAPIで取得する。
- `new_car_consultation_view`: 新車の相談案内が表示された。対象セクションごとに1ページ読み込み1回。
- `new_car_consultation_click`: 新車相談の電話リンクが押された。通話成立や問い合わせ完了ではない。
- `new_car_flow_click`: 新車ページ内の購入フローへ進むリンクが押された。
- `new_car_guide_click`: 新車の納期・県外購入の記事へ進むリンクが押された。
- `new_car_service_click`: 新車関連記事から新車の購入相談ページへ進むリンクが押された。
- 上記の新車イベントは2026-10-04の追加改善の公開以降を対象にする。個別のイベント名で区別するため、カスタムディメンションの追加登録は不要。定期レポートでは中古車と別表にし、参照元・ページ・新規再訪ごとに確認する。表の数字は行動集計であり、同じセッションが記事→相談→電話の順に進んだことを証明するファネルではない。汎用CTA・電話イベントと合算して問い合わせ件数にしない。
- `indeed_apply_click`: Indeedの求人ページへ遷移した
- `cta_click`: CTAボタンが押された
- `recruit_link_click`: 採用導線が押された
- `recruit_form_submit_start`: 採用フォーム送信が開始された
- `recruit_form_submit_success`: 採用フォーム送信が成功した
- `recruit_form_submit_error`: 採用フォーム送信でエラー応答を受けた
- `scroll_depth`: 25%、50%、75%、90%到達

## 改善判断

- 表示回数が多いがクリックが少ない: タイトルとdescriptionを改善
- 電話番号案内は開かれるが発信が少ない: 営業時間、相談できる内容、電話後の流れをCTA周辺で明示
- 閲覧は多いが電話番号案内も発信も少ない: CTA位置、文言、電話導線を改善
- 記事は読まれるがサービスページへ移動しない: 記事内リンクを追加
- 採用フォーム開始は多いが成功が少ない: 入力項目、エラー表示、GAS応答を確認
- Goo-net遷移が多い: 掲載車の確認意向として読む。仕入れ相談の案内表示・相談導線への行動も確認し、まず既存記事と相談ページのつながりを整える。同じ訪問者の再確認や業者の閲覧もあり得るため、記事を増やす根拠や問い合わせ数にはしない。

## 2026-10-04の追加改善と評価時期

- 2026-08-09〜2026-10-03の56日間をGA4 APIで確認。中古車ページは14閲覧、10ユーザー、12セッション、Goo-net遷移9回。新車ページは2閲覧、2ユーザー、2セッション、用品記事は1閲覧、仕入れ・修理の記事は3閲覧。母数が少なく、新車の需要増や業者・個人の比率は断定しない。
- 新規のメーカー別記事を追加せず、既存の新車ページ・国内メーカー記事・用品記事を改善。納期の根拠とメーカー公式リンクは既存の納期記事にまとめ、サービスページは相談できること、必要な条件、相談先に集中させる。国内メーカー記事の中古車ページ向けCTAは新車ページへ修正。
- 新車ページの検索タイトルは維持し、descriptionのみ福山市・希望車種・予算・必要な時期・用品・購入後の整備が伝わる文へ変更。検索結果ではGoogleが別の本文を表示する場合もあるため、指定文が表示されたことまで計測したとは扱わない。
- 2026-11-01以降に28日程度の同期間比較を行う。表示数・順位・対象検索語の変化を併記し、CTRだけで成否を決めない。今回の文章と導線を同時に変えた結果を、厳密なA/Bテストやdescription単体の効果として説明しない。
- 直前に公開した中古車の仕入れ相談導線は維持する。短期間の数字で再変更しない。新車の閲覧が少なければ、内容の量産より検索表示・既存記事からの流入を先に確認する。
